## Архитектура

`rey-core` владеет Ghost, SQLite, диалогом, контрактом провайдера, ограниченными инструментами, аудио и играми. `rey-desktop` отвечает за нативное окно, отображение состояний и работу с аудиоустройствами. CLI использует те же конфигурацию и ядро. Контроллер аватара получает события независимо от модели. Альманах доступен отдельными разделами через инструмент чтения.

Модули общения, игровых правил и процессов движков взаимодействуют через данные позиции и события. Это оставляет место для будущих фоновых задач и других оболочек. Характер версионируется, ядро личности читается при запуске и доступно для проверки SHA-256.

## План и данные

1. Запустить Rust с новой БД. Проверить диалог, инструменты, GUI и импорт на копии.
2. Подключить голосовой worker и проверить STT/TTS отдельно на целевой конфигурации.
3. Проверить UCI/USI, игры и сохранение партий, затем проверить платформенные сборки.
4. Перед переходом остановить старый клиент. Выполнить `cargo run --bin rey -- migrate`. Команда копирует старую БД в новый файл через SQLite Backup API и отказывается перезаписывать существующий файл. Альтернативные пути задаются через `--from` и `--to`.
5. Для отката открыть прежний Python-клиент с его исходной БД. Сообщения, появившиеся после импорта, находятся в новой БД. Резервная копия создаётся командой `rey backup путь.db`.

Старые и новые файлы следует хранить независимо. Миграция переносит всю старую БД, в том числе приватные записи и историю событий.
