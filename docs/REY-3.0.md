# Отчёт по Rey 3.0

| Этап | Статус |
| --- | --- |
| 1. Rust Foundation | Workspace, общая конфигурация, CLI, Ollama, llama.cpp и перенос SQLite. |
| 2. Ghost | Исходный промпт, проверка SHA-256, версионируемый характер, Альманах, типизированные инструменты чтения памяти и Markdown-заметки. |
| 3. Desktop Shell | Нативный egui/eframe, история и отмена диалога, настройки, системный статус, кэш и анимации аватара v1.1. |
| 4. Voice | Запись и воспроизведение в Rust. Независимый worker Faster‑Whisper и Qwen3‑TTS, WAV/MP3/OGG, удалённый API и прежний адаптер Telethon. |
| 5. Chess | Доска, правила, часы, Stockfish, PGN/FEN, история, игровой чат и разбор позиции. |
| 6. Shogi | Доска с кандзи, комадаи, сбросы, превращения, правила окончания, YaneuraOu, SFEN/USI и CSA. |
| 7. Stabilization | Проверки Cargo и CI для Linux и Windows. Аппаратные проверки вынесены ниже. |

Ядро, история, правила, процессы и нативный интерфейс перенесены в Rust. Python остаётся в локальном или удалённом inference worker для моделей и в совместимом Telegram-адаптере. Прежние команды Python доступны для отката. SQLite переносится снимком с прежними идентификаторами. Разделы Альманаха загружаются по запросу. Архитектурное разделение позволяет подключать другие модели и оболочки без переноса личности. [План миграции](MIGRATION.md)

Из пакета v1.1 извлечены все файлы, включая 11 эмоций, анимации, превью и документацию. Уникальные исходные референсы v1.0 сохранены в `assets/references/`. Архив и побайтовые дубликаты удалены после сверки. Из репозитория удалены временные результаты старых тестовых запусков.

## Выполненные проверки

- `cargo fmt --all --check`, `cargo clippy --workspace --locked --all-targets -- -D warnings` и сборка Linux `cargo build --release --workspace --locked` прошли. В основном наборе прошло 24 теста на Rust.
- Импорт и резервное копирование через CLI проверены на базе, созданной прежним Python-кодом. Исходная и новые базы содержат те же сообщения, идентификаторы заметок и события. Повторный импорт поверх существующего файла отклонён.

- Нативное окно Linux запущено под X11 и Wayland. В X11 проверены ввод, Markdown с блоком кода, отмена генерации, переходы аватара, доски обеих игр и сохранение партии. После настройки зависимостей отдельно проверен обычный запуск из корня проекта. Desktop получил ответ через существующий защищённый llama-server и сохранил ответные ходы Stockfish и YaneuraOu в завершённых партиях. Реальная Ollama также ответила через CLI.
- Отдельный интеграционный тест сыграл по три легальных полухода реальными Stockfish 19 и YaneuraOu MaterialLv1 9.00 на Linux.
- Faster‑Whisper `tiny` обработал WAV, MP3 и OGG/Opus, а `small` распознал тестовую русскую фразу из WAV на настроенном компьютере. Qwen3-TTS 1.7B VoiceDesign синтезировал фразу на CPU. FFmpeg и ffprobe подтвердили PCM WAV, MP3 и OGG/Opus.
- Все 32 теста прежней Python-версии прошли с Telethon, Hugging Face и FFmpeg.
- Два Rust-приложения скомпилированы и слинкованы для Windows x86-64 через MinGW. В GitHub Actions добавлена нативная матрица Windows/Linux.

На настроенном Linux-компьютере провайдер для обычного чата — локальная Ollama с Qwen 2.5 1.5B. Короткий запрос занимал около 9 секунд при загрузке модели и менее секунды после прогрева. Уже установленный llama.cpp с Qwen 3.5 9B остаётся вторым провайдером. Его короткий ответ в отдельном замере занимал около 19–30 секунд. Время зависит от длины ответа и нагрузки на компьютер.

## Ограничения и дальнейшее развитие

Остаются проверки VoiceClone с пользовательским референсом, инференса на RTX 3060, физических аудиоустройств и запуска на Windows 10/11. На настроенном компьютере Qwen3-TTS работает на CPU. Настройки Desktop действуют в открытом сеансе. Постоянные значения берутся из `.env`. Процессы движков ограничены параметрами и таймаутом. Изоляция всей файловой системы через платформенную песочницу требует отдельной работы.

Следующие расширения — импорт KIF, просмотр и анализ сохранённых партий, японский бёёми, более широкий разбор редких мёртвых шахматных позиций и переход Telegram на Rust-ядро. Границы для фоновой консолидации памяти и внешних оболочек уже совпадают с разделением Ghost/Shell. Их жизненный цикл и синхронизация нескольких устройств остаются будущей работой.
